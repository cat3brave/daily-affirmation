# 検証の事前確認と実行記録

この記録は、検証の未実行・環境停止・アプリの失敗を混同しないための補助票です。既存の `AGENTS.md`、必須コマンド、CI、品質ゲートを置き換えたり緩和したりしません。

## 実行前の固定確認

1. `git status -sb` と `git status --short` で開始時の差分を記録する。
2. `package.json` に実行予定のscriptが存在することを確認する。
3. Playwrightを使う場合、既定ブラウザーの実体と実行権限を確認する。

   ```sh
   node -e "const fs=require('node:fs');const {chromium}=require('@playwright/test');const p=chromium.executablePath();fs.accessSync(p,fs.constants.X_OK);console.log(p)"
   ```

   `command -v chromium` だけでは、ラッパーの参照先欠落やPlaywrightが使う実体を確認できない。事前確認の成功も、実際のE2E成功の代わりにはしない。
4. buildに環境変数が必要な場合、既存手順で許可された非秘密のplaceholderか、対象環境の安全な設定を使う。値は記録やログへ転記しない。必要な設定がなければ「アプリ失敗」ではなく「環境停止」として区別する。
5. 実行前後で対象外ファイルが変わっていないか確認する。開発サーバーやフレームワークが `AGENTS.md` などを自動変更した場合は、対象差分へ混ぜず、原因と最終状態を記録する。

## 結果の分類

各コマンドは次のいずれか一つで記録する。

| 分類 | 意味 | ゲート上の扱い |
| --- | --- | --- |
| `pass` | 対象コマンドが期待した検証を完了した | 根拠として利用可能 |
| `fail` | テスト不合格、静的解析違反、脆弱性検出など対象の問題を観測した | 解消まで成功扱いにしない |
| `blocked` | ブラウザー不在、必要設定不足、通信制限などで検証を開始・完了できない | 未検証。例外条件なしにpassへ変換しない |
| `not-run` | 対象外、先行失敗による停止などで実行していない | 理由を記録し、成功扱いにしない |

終了コードだけで分類しない。たとえば `npm run audit:prod` は `--audit-level=high` のためmoderateの検出があっても終了コード0になり得る。コマンド名、終了コード、severity別件数、修正可能版を分けて記録し、「脆弱性なし」と読み替えない。

## 1回分の記録テンプレート

```md
### 実行情報

- 日時:
- base SHA:
- head SHA:
- 対象変更:
- ローカル検証レベルと理由:
- 実データ・秘密情報・実AI送信: なし / あり（許可根拠）

| コマンド | 目的 | 所要時間 | 終了コード | 分類 | 観測事実・成果物 |
| --- | --- | ---: | ---: | --- | --- |
| `...` | ... | ...秒 | ... | pass/fail/blocked/not-run | ... |

### 差分とゲート

- `git diff --check`:
- `git diff --stat`:
- `git diff --name-only`:
- 最終 `git status --short`:
- 必須ゲートのfail/unknown:
- 再試行する条件:
- 未確認:
```

## 再試行と停止

- 同じ入力・同じ環境・同じ失敗を、原因修正なしで繰り返さない。
- `blocked` はテスト成功ではない。Chromium制限の扱いは `AGENTS.md` の明示条件に従う。
- 先行コマンドを誤った環境で実行した場合は、理由を残し、許可された正しい条件で一度だけ確認し直す。
- セキュリティ監査の検出、必須buildの停止、対象外ファイルの予期しない変更は個別に記録する。一つの後続成功で打ち消さない。
- 実装と評価基準の変更は別PRにし、ハーネス変更の合格をアプリ本体の品質向上とみなさない。

## 固定基準での改善確認

この補助票の改善効果は、次の二つを同じ記録形式で区別できることで確認する。

1. 既知の合格例: 必要な実体と設定があり、コマンドが完了した場合は `pass` と記録できる。
2. 既知の停止例: Playwright既定ブラウザーがない場合は `blocked`、監査がmoderateを報告して終了コード0の場合は検出内容を残せる。

これは検出と記録の確認であり、ブラウザー不足や依存関係の問題を解消したこと、利用者体験が改善したことを意味しない。
