# 入力保持の評価ケース

疲れている利用者が、入力途中の文章を意図しない操作で失わないことを確認する。ここで定義するケースは、該当する操作を変更するときの評価例であり、すべてのPRへ一律に追加する必須ゲートではない。必要な検証範囲は `AGENTS.md` を優先する。

## INPUT-IME-001: 日本語IMEの変換確定Enter

### 適用条件

- テキスト入力でEnterを実行操作として扱う。
- 日本語などのIMEによる文字変換を利用できる。
- 実行後に入力を消去、送信、保存、画面遷移のいずれかを行う。

Enterを実行操作にしていない入力欄や、複数行入力で改行を受け付ける操作には、このケースを機械的に適用しない。

### 固定入力

- 入力文字列: `絶対に失敗する`
- 実データ、秘密情報、外部AI送信: 使用しない
- 実行回数の初期値: 0

### 手順と期待結果

| 手順 | 操作 | 期待結果 |
| --- | --- | --- |
| 1 | 固定文字列を入力する | 入力値が固定文字列と一致し、実行回数は0 |
| 2 | IME変換中を示す `isComposing: true` のEnterを発生させる | 実行回数は0のまま、入力値を保持 |
| 3 | 変換終了後の通常Enterを1回発生させる | 実行回数が1。仕様どおりの後処理だけを行う |
| 4 | 初期状態から明示的な実行ボタンを1回押す | 実行回数が1。通常Enterと同じ結果 |
| 5 | 空入力または空白だけでEnterとボタンを操作する | 実行回数は0 |

手順2だけを通して通常Enterを壊していないか、手順3〜5を同じ固定基準で確認する。

### 証拠の記録

- 対象コンポーネントと入力識別子。
- composition中／終了後のイベント条件。
- 実行callbackまたは通信の呼び出し回数。
- 操作前後の入力値。
- 使用した単体テスト、E2E、実端末・IMEの種類。
- 実端末確認がなければ「各IMEで確認済み」と書かない。

コンポーネント単体テストはイベント分岐の回帰証拠にできるが、OS・ブラウザー・IMEの組み合わせ全体を保証しない。実画面や実端末の確認が必要な変更では、その未確認を別に残す。

### 既知の失敗と合格の照合

- 失敗例: `e.key === "Enter"` だけで実行する実装は、手順2でも実行回数が1になり、入力保持条件を満たさない。
- 合格例: `MaybeCloudCard.test.tsx` の「日本語入力の変換確定中はEnterで放たず入力を保持する」は手順2を、既存の通常Enter・ボタン・空入力テストは手順3〜5を確認する。

この照合は既知の不具合を検出し、既存の合格操作を誤って拒否しないことの確認に限る。利用者の安心感、満足度、心理的効果を自動テストから推測しない。

## 評価結果の書式

`EXECUTION_RECORD.md` の表へ、対象ケースID、コマンド、終了コード、分類、呼び出し回数と入力保持結果を記録する。環境制約で実端末確認ができない場合は `blocked` または未確認として残し、単体テスト成功で置き換えない。
